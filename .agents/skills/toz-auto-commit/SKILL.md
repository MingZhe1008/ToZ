# ToZ 修改后自动提交并推送

将每轮已完成、可审查的项目修改保存为 Git 提交并推送到远程，在最终交付前执行；无需逐次询问。按任务形成完整提交，不在每次写文件或尚未完成实现时制造提交。

## 项目边界

- 仅用于包含本技能及项目根目录 `AGENTS.md` 的 ToZ 仓库。通过 `git rev-parse --show-toplevel` 确认根目录，不套用到父目录、其他仓库或全局配置。
- 用户明确要求不提交、暂缓提交或只读检查时，不执行自动提交；要求不推送或仅本地提交时，保留本地提交并跳过推送。
- 默认沿用当前分支，不自动新建或切换分支。用户要求使用某个分支时按其要求处理。
- Detached HEAD、未解决的合并冲突或缺少提交身份时，先说明具体阻碍；不得猜测身份、改写历史或强行提交。

## 提交流程

1. 开始修改前记录 `git status --short`、当前分支及相关文件已有差异，区分用户原有改动和本轮任务。
2. 完成修改，仅运行本轮修改内容及其直接影响行为的定向验证；按相关用例、文件或交互选择范围，不默认运行全量测试或完整源码 / 打包程序验收。只有用户明确指定完整测试或完整验收时才执行对应完整流程；提交、推送或打包本身不是全量授权。纯文案 / 样式检查对应界面，纯文档或技能配置修改检查内容、引用和差异。失败时只修复并重跑相关检查，记录实际范围与未运行项；环境或既有问题限制如实说明。
3. 按 [文档维护规范](../../../docs/文档维护规范.md) 对照本轮代码差异检查对应文档与项目现状是否同步，验证记录是否只写实际检查；修复冲突或遗漏后再提交。确实无说明变化时记录原因。审查 `git diff` 和待提交文件，确认没有密钥、运行数据或构建产物。遵循 `.gitignore`，不使用 `git add -f` 加入排除内容。
4. 用明确路径或差异分块暂存本轮改动。已有用户修改与本轮修改混在同一文件时，先可靠分离；无法分离时说明限制，不擅自撤销或提交无关内容。不要使用无范围的 `git add .` 或 `git add -A`。
5. 检查 `git diff --cached --stat`、实际暂存差异和 `git diff --cached --check`。Markdown 有意的双空格换行不算排版错误。若已有暂存的无关内容，保留其状态，并确保本次提交不包含它们。
6. 若有本轮变更，自动创建普通提交，消息说明具体结果，例如 `fix: 修复日期选择器切月`、`docs: 更新安装说明`、`chore: 添加项目自动提交技能`。没有本轮差异则不创建空提交。不得自动使用 `--amend`、`--no-verify`、强制推送或破坏性重置。
7. 用 `git log -1` 和 `git status --short` 核实提交结果，保留所有无关未提交改动。随后执行下述远程推送；最终回复简要报告实际更新的文档、验证情况、分支、提交号和推送结果。

## 远程操作

根目录 AGENTS.md 已持续授权每轮完成后自动推送，不再单独询问。没有本轮新改动时不创建空提交；同一任务已有待推送的相关提交仍可推送。

- 已有上游时沿用其远程与分支。没有上游且仅有 origin 远程时，推送到 origin 的当前同名分支并设置上游；无远程或存在多个不明确目标时报告阻碍，不猜测。
- 推送前获取目标远程状态，检查待推送范围，确保没有无关提交；使用普通 git push，保留远程历史。
- 推送后用远程引用核对目标提交号与本地 HEAD 一致，分别报告本地提交成功与远程推送成功。不得仅凭本地 ahead 状态或提交输出声称已上传。
- 网络、认证、钩子、分支保护或非快进拒绝时，明确报告失败原因并保留本地提交；不使用 --force / --force-with-lease、不绕过钩子、不自动改写历史。若无法安全解决，则停止推送，交付时说明阻碍。
- 自动推送不包含创建本地分支、合并或发布版本；这些仍按用户明确要求执行。

提交被钩子拒绝时，修复本轮问题后重试；不能安全解决的签名、权限或身份问题应报告阻碍，不绕过检查或反复盲目重试。
