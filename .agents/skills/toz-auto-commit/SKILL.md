# ToZ 修改后自动提交

将每轮已完成、可审查的项目修改保存为 Git 提交，在最终交付前执行。按任务形成完整提交，不在每次写文件或尚未完成实现时制造提交。

## 项目边界

- 仅用于包含本技能及项目根目录 `AGENTS.md` 的 ToZ 仓库。通过 `git rev-parse --show-toplevel` 确认根目录，不套用到父目录、其他仓库或全局配置。
- 用户明确要求不提交、暂缓提交或只读检查时，不执行自动提交。
- 默认沿用当前分支，不自动新建或切换分支。用户要求使用某个分支时按其要求处理。
- Detached HEAD、未解决的合并冲突或缺少提交身份时，先说明具体阻碍；不得猜测身份、改写历史或强行提交。

## 提交流程

1. 开始修改前记录 `git status --short`、当前分支及相关文件已有差异，区分用户原有改动和本轮任务。
2. 完成修改，运行与改动相关的验证。源码修改运行相应测试；纯文档或技能配置修改检查内容、引用和差异。修复本轮引入的失败；若验证受到环境或既有问题限制，如实说明。
3. 审查 `git diff` 和待提交文件，确认没有密钥、运行数据或构建产物。遵循 `.gitignore`，不使用 `git add -f` 加入排除内容。
4. 用明确路径或差异分块暂存本轮改动。已有用户修改与本轮修改混在同一文件时，先可靠分离；无法分离时说明限制，不擅自撤销或提交无关内容。不要使用无范围的 `git add .` 或 `git add -A`。
5. 检查 `git diff --cached --stat`、实际暂存差异和 `git diff --cached --check`。Markdown 有意的双空格换行不算排版错误。若已有暂存的无关内容，保留其状态，并确保本次提交不包含它们。
6. 若有本轮变更，自动创建普通提交，消息说明具体结果，例如 `fix: 修复日期选择器切月`、`docs: 更新安装说明`、`chore: 添加项目自动提交技能`。没有本轮差异则不创建空提交。不得自动使用 `--amend`、`--no-verify`、强制推送或破坏性重置。
7. 用 `git log -1` 和 `git status --short` 核实提交结果，保留所有无关未提交改动。最终回复简要报告验证情况、分支和提交号。

## 远程操作

自动提交是本地持久化步骤，不自动包含 `git push`。用户明确授权推送时再推送到指定远程和分支，并核对远程提交号；保留远程历史，不强制覆盖。

提交被钩子拒绝时，修复本轮问题后重试；不能安全解决的签名、权限或身份问题应报告阻碍，不绕过检查或反复盲目重试。
