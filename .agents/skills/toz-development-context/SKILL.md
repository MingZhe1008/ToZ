# ToZ 开发上下文入口

先接续项目现状，再执行用户的新需求；不要求用户重新提供此前的聊天记录。本技能仅在本仓库内生效，由根目录 [AGENTS.md](../../../AGENTS.md) 作为新会话入口。

## 首次进入会话

1. 确认 Git 根目录、当前分支及 `git status --short`，记录已有改动。读取根目录规则，保留用户未提交内容。
2. 先阅读 [项目现状](../../../docs/项目现状.md)，再阅读 [README.md](../../../README.md) 并查看根目录 `package.json` 的版本、脚本与实际依赖，确认当前实现、限制和运行方式。
3. 阅读 [开发需求文档](../../../docs/开发需求文档.md) 的产品范围、日期与时长规则、数据一致性以及最新补充章节。阅读 [Windows 安装版说明](../../../docs/Windows安装版说明.md) 的当前版本说明和数据 / 构建部分，并读取 [文档维护规范](../../../docs/文档维护规范.md)，分清已实现能力、历史方案与未来规划。
4. 阅读 [验证记录](../../../docs/验证记录.md) 的最新版本部分，了解此前验证范围和已知边界；历史通过记录不能代替本次验证。随后按下表补读本轮任务对应内容。
5. 对照相关实现和测试，确认需求涉及的实际行为后开始修改。当前用户要求优先；文档间有冲突时，结合较新的补充、当前代码和测试判断，无法确定且影响实现时再询问。

只对新会话执行完整的初始加载；同一会话可复用已读且未变化的内容。不要为了建立上下文遍历全部运行数据、历史产物或聊天存档。

## 按任务加载对应文档与代码

| 任务 | 补读文档 | 实现入口（相对仓库根目录） |
| --- | --- | --- |
| 任务日期、延期、完成、子任务 | 开发需求中的日期规则、核心流程、数据结构及最新补充 | `prototype/domain.mjs`、`prototype/lifecycle.mjs`、`prototype/app.mjs` 及对应测试 |
| 周期任务、农历、跨日安排 | 开发需求和安装说明中的周期、农历、日期区间部分 | `prototype/recurrence.mjs`、`prototype/lunar.mjs`、`prototype/calendar.mjs`、`prototype/gantt.mjs` |
| 页面、菜单、主题、设置、浮窗交互 | [视觉与交互规范](../../../docs/视觉与交互规范.md)，以及安装说明中的灰色主题、浮窗和设置部分 | `prototype/index.html`、`prototype/app.mjs`、相关 CSS、`prototype/desktop-ui.mjs`、`desktop/main.cjs` |
| SQLite、备份、回收站、删除 | 开发需求中的一致性、本地保存和回收站补充；安装说明中的数据部分 | `desktop/store.cjs`、`prototype/trash.mjs`、`prototype/lifecycle.mjs`、`desktop/preload.cjs` |
| Windows 安装、自启动、构建 | 安装说明中的安装、客户端设置、构建与验证部分 | `electron-builder.json`、`build/`、`scripts/`、`desktop/startup.cjs` |
| 修改项目规则或技能 | 根目录规则与实际涉及的项目技能 | `AGENTS.md`、`.agents/skills/` |

按功能读取必要的源文件和测试，不把表格作为完整文件清单；引用发生变化时通过搜索定位现有入口。

## 开发时持续保留的项目约束

- 当前主产品是 Windows 离线 Electron 客户端与透明浮窗，SQLite 为原生存储；浏览器原型另用 localStorage。iOS 是预留方向，不能描述为已交付。
- 首次实际开始、最初计划和延期历史有专门约束；计划开始可调整，勿与首次实际开始混淆。普通编辑维持历史只追加；明确的回收站永久删除走独立事务与确认流程。
- 沿用现有 macOS 风格、中性灰选中与控件、多彩分区标记和绿色完成状态。实际默认主题、版本及行为以当前代码和最新说明为准，不能沿用旧章节的浅色或蓝色方案。
- 已安装应用可能包含真实数据。验证用仓库内 `.runtime/` 的独立目录，不覆盖正式 `%APPDATA%\ToZ` 数据、启动项或运行安装器替换正式应用来做验收。
- 数据库、依赖、构建与临时验收产物遵循 `.gitignore`；不要为读取上下文而导出真实用户任务。

## 本轮工作完成后

运行与改动匹配的测试或隔离验收。按文档维护规范的映射表，对照本轮差异同步项目现状及对应功能文档；修正旧正文中的相反描述，不只追加变更说明。验证记录只写本次实际执行的检查。纯文档或技能变更不必重建安装包；无需改动功能文档时说明原因。

最后应用 [toz-auto-commit](../toz-auto-commit/SKILL.md)，提交本轮相关改动并自动推送到当前分支的上游；没有上游时按该技能选择目标。报告实际更新的文档、验证结果、分支、提交号及远程核对结果。用户当轮要求不提交或不推送时优先执行，不强制覆盖远程。
