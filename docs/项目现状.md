## 产品与技术基线

- 已实现 Windows x64 离线 Electron 客户端、独立透明浮窗、NSIS 安装包；保留浏览器交互原型。iOS、云同步尚未实现。
- 开发基线 Node.js 24；Electron 44.9.1，SQLite 使用 `node:sqlite`。运行不依赖账号或业务服务器。
- 原生客户端使用真实本机日期及 SQLite；浏览器原型固定演示日期 `2026-10-20`，使用 localStorage。两种数据不自动互通，可显式导出 / 导入。
- 新安装默认深色，旧有浅色选择保留。黑底白字标识、灰色导航图标与选中背景；分区色、完成绿色和足迹语义色保留。
- 界面术语统一为“分区”；数据字段仍使用 `project` / `projects`，不应仅为统一文案改写旧数据结构。

## 当前数据契约

- SQLite 表为 `meta(key,value)`、`tasks(id,started,initial_plan,data)`、`events(id,task_id,data)`。任务完整对象及内嵌 `subtasks` / `events` 保存在 JSON 中；不是初稿的独立 work_logs、projects 或多级子任务表。
- 常用任务字段：`createdAt`、`planStart`、`plan`、`initialPlan`、`started`、`startedAt`、`startedTimezone`、`done`、`completedDate`、`top`、`deletedAt`、`deletedByProject`。旧数据可能缺少后来新增的可选字段，不补造历史事实。
- 周期模板在 `recurrences`，期次使用 `repeatId` / `repeatDate`；模板 `excludedDates` 保存被永久删除的日期，生成时跳过。普通保存不能改写规则、重新启用停止的周期或抹掉排除日期。
- `preferences` 保存 `projectColors`、`projectTrash`、`menuOrder`、`taskOrder`、`widgetProject`。`projectTrash` 的删除模式决定恢复方式；目标已被永久删除时使用 `targetPurged` 标记。
- `Store.commit` 承担正常编辑保护；`Store.purge` 是仅作用于回收站对象的独立事务；`Store.restore` 是确认后的全量替换并预先创建安全副本。三者不要混为同一编辑路径。
- 永久删除任务清除任务及其事件行；永久删除子任务保留父任务原有足迹；旧备份和已导出文件不随之清除。确认时的版本发生变化则拒绝执行，要求重新确认。

## 尚未实现或尚未完整验证

- iOS、云同步、账号、多设备同步、实际工时、暂停 / 继续、独立子任务日期及多级子任务、独立归档、外部硬截止、优先级、CSV 报表、撤销改期的排除统计。
- 已记录首次开始时区，但持续天数当前采用保存的开始 / 完成日期与本机当前日期的日差；尚未实现“始终按首次开始时区计算今天”。
- 新建可不排期；现有调整计划接口要求有效的完成日期，不提供清空已有完成日期的操作。
- 不提供桌面图标后嵌入，不保证 Win+D 后浮窗仍可见；代码签名尚未配置；不把 Windows 10、全部 DPI / 多显示器组合及性能目标描述为已全面验收。
- 设置页备份提示写“十四天”，底层实际保留最近十四份有写入日期的快照；严格按十四个自然日清理尚未实现，后续变更需同步文案。
- 当前支持 schema 1 JSON 的校验与兼容；没有通用多版本数据库迁移向导、完整磁盘故障演练或所有异常的持久重试界面。
