核对日期：2026-10-25。应用基线：`package.json` 中的 **v1.1.5**。原 `V1.0.0` 分支已合并至 `main` 并更名为 `develop`；以下能力已纳入主分支：增加 Windows 邮箱验证码账号、可绑定多个邮箱、独立账号数据库与多电脑云同步，已部署 Linux IP HTTPS 服务。v1.1.1 未登录时先选择账号登录或离线使用，再创建任务主窗及浮窗；退出账号返回启动选择。v1.1.2 侧栏底部改为可上传头像的账号菜单，账号页首帧读取当前账号，保存与云同步状态分开说明。v1.1.3 托盘悬停提示随账号及同步状态更新，不再固定标记为离线待办；更新程序及新建快捷方式描述。v1.1.4 支持账号昵称编辑及跨电脑同步，保留邮箱身份显示。v1.1.5 首次登录数据处理改为主题一致的应用内双选项弹层，默认取消，保护本机版本。安装向导及日期 / 历史规则保留。详情见 [云同步部署说明](云同步部署说明.md)。

本页是新会话的现状入口；详细业务规则见 [开发需求文档](开发需求文档.md)，使用和构建见 [Windows 安装版说明](Windows安装版说明.md)，界面要求见 [视觉与交互规范](视觉与交互规范.md)。历史验收见 [验证记录](验证记录.md)，后续更新遵循 [文档维护规范](文档维护规范.md)。文档不是执行结果证明，开发前仍需核对当前代码、分支和用户要求。

## 产品与技术基线

- Android `1.1.5-android.3` 移植工程已加入 `develop`：原生 Activity / WebView + 安卓 SQLite，复用 Store / Cloud 及任务界面，手机触控导航与平板多栏布局；真机能力尚待验收。安装与边界见 [Android 安装与开发说明](Android安装与开发说明.md)。
- 已实现 Windows x64 离线 Electron 客户端、独立透明浮窗、NSIS 安装包及可选账号云同步；保留浏览器交互原型。iOS、手机号验证码及绑定尚未实现。
- 开发基线 Node.js 24；Electron 44.9.1，SQLite 使用 `node:sqlite`。离线使用不依赖账号；多电脑同步需要登录并连接云服务。服务端 Node 24 + SQLite + QQ SMTP + Nginx / IP HTTPS。
- Windows / Android 使用真实本机日期及 SQLite；浏览器原型固定演示日期 `2026-10-20`，使用 localStorage。安卓与 Windows 可经账号同步或 JSON 导入 / 导出交换数据，数据库文件不直接互换；浏览器原型不接入账号服务。
- 新安装默认深色，旧有浅色选择保留。黑底白字标识、系统界面字体、中性表面与选中背景；分区色、完成绿色和足迹语义色保留。新用户浮窗背景不透明度默认 88%，保留旧用户已存值。
- 界面术语统一为“分区”；数据字段仍使用 `project` / `projects`，不应仅为统一文案改写旧数据结构。

## 当前数据契约

- SQLite 表为 `meta(key,value)`、`tasks(id,started,initial_plan,data)`、`events(id,task_id,data)`。任务完整对象及内嵌 `subtasks` / `events` 保存在 JSON 中；不是初稿的独立 work_logs、projects 或多级子任务表。
- 常用任务字段：`createdAt`、`planStart`、`plan`、`initialPlan`、`started`、`startedAt`、`startedTimezone`、`done`、`completedDate`、`top`、`deletedAt`、`deletedByProject`。旧数据可能缺少后来新增的可选字段，不补造历史事实。
- 子任务可选 `planStart` / `plan` 成对保存；旧子任务缺省等同不设日期。未删除子任务的起止包含于父任务计划范围，日期编辑追加 `subtask_schedule`，删除的子项恢复前重新校验。沿用 schema 1 内嵌 JSON，无数据库列迁移。
- 周期模板在 `recurrences`，期次使用 `repeatId` / `repeatDate`；模板 `excludedDates` 保存被永久删除的日期，生成时跳过。普通保存不能改写规则、重新启用停止的周期或抹掉排除日期。
- `preferences` 保存 `projectColors`、`projectTrash`、`menuOrder`、`taskOrder`、`widgetProject`。`projectTrash` 的删除模式决定恢复方式；目标已被永久删除时使用 `targetPurged` 标记。
- `Store.commit` 承担正常编辑保护；`Store.purge` 是仅作用于回收站对象的独立事务；`Store.restore` 是确认后的全量替换并预先创建安全副本。三者不要混为同一编辑路径。
- `Store.applyCloud` 校验同步文档和本机版本，生成安全副本后应用远端删除 / 冲突结果；普通编辑仍走原有保护。`cloudBase` 是账号本机最后成功同步基线；服务端按账号保存文档版本与最近三十个旧版本。
- 永久删除任务清除任务及其事件行；永久删除子任务保留父任务原有足迹；旧备份和已导出文件不随之清除。确认时的版本发生变化则拒绝执行，要求重新确认。

## 尚未实现或尚未完整验证

- Android 真机安装 / 升级、旋转分屏、软键盘、安全区、Keystore、原生 SQLite 与系统文件选择、头像及 Windows ↔ Android 真实联机尚未验收；桌面小组件、安卓悬浮窗、通知提醒、后台持续同步及正式发行签名尚未实现。
- iOS、手机号验证码 / 绑定、设备管理与全设备注销、增量同步、实际工时、暂停 / 继续、子任务独立提醒及多级子任务、独立归档、外部硬截止、优先级、CSV 报表、撤销改期的排除统计。同步已通过隔离双实例验证，未在两台实体 Windows 电脑上联机验收；云端尚无异地备份。
- 已记录首次开始时区，但持续天数当前采用保存的开始 / 完成日期与本机当前日期的日差；尚未实现“始终按首次开始时区计算今天”。
- 新建可不排期；现有调整计划接口要求有效的完成日期，不提供清空已有完成日期的操作。
- 新安装向导已完成隔离界面检查和构建；真实安装、UAC、升级、卸载及全部 DPI 组合尚未在本轮执行。使用系统 DPI 缩放；实际安装采用细圆角绿色进度条与阶段百分比：提取 0–20%、校验后 30%、引擎成功及程序存在后 95%、启动偏好处理后 100%；引擎等待期间保持 30%，并非逐文件复制百分比。
- 不提供桌面图标后嵌入，不保证 Win+D 后浮窗仍可见；代码签名尚未配置；不把 Windows 10、全部 DPI / 多显示器组合及性能目标描述为已全面验收。
- 自动备份实际保留最近十四份有写入日期的快照；v1.0.0 设置文案已改为“最近十四份”。严格按十四个自然日清理尚未实现。
- 当前支持 schema 1 JSON 的校验与兼容；没有通用多版本数据库迁移向导、完整磁盘故障演练或所有异常的持久重试界面。
