# ToZ 网页版

版本 `1.1.5-web.1`，2026-11-02 部署核对。正式入口：[https://www.lyy12.cn/toz/](https://www.lyy12.cn/toz/)，域名 HTTP 自动升级 HTTPS，`/toz` 跳转到 `/toz/`，全程保持域名。原 [IP 入口](https://82.157.65.130/toz) 继续保留。与 Windows、Android 共用任务规则及账号同步服务，本轮只修改部署配置，不递增客户端版本。

## 使用

打开即进入空的本机工作台，使用设备真实日期。可创建、开始、完成、延期任务，管理子任务、分区、周期 / 农历、日历、甘特图及回收站。手机使用底部导航和侧栏抽屉，宽屏展开侧栏与详情。设置在当前网页内打开，不提供 Windows 托盘、启动项或桌面浮窗。

从左下角账号入口或设置 → 账号与同步，使用邮箱验证码登录。手机可先打开左上角导航。登录同一邮箱后，可与 Windows 和 Android 交换任务；首次登录有离线数据时先选择保留或复制，原离线副本保留。每十五秒及恢复前台时尝试同步，可手动重试；冲突需确认。昵称、头像和邮箱绑定沿用现有账号接口。

数据页支持导出 JSON、从 JSON 恢复和回收站。恢复先另存安全副本，确认时本机版本变化则拒绝继续。日期、首次开始、最初计划、历史和永久删除约束沿用共享 Store。

## 浏览器数据边界

域名和 IP 是不同的浏览器来源，登录状态和离线副本不自动迁移。首次通过域名访问需重新登录，同步过的任务会从同一账号拉取；尚未同步的 IP 本机任务应先在旧 IP 页面导出 JSON，再在域名页面恢复。原 IP 页面及其数据仍保留。浏览器缓存旧 HTTP 301 时可能继续显示旧跳转，可直接打开新的 HTTPS 域名地址；不要为修复跳转而清空网站任务数据。

- 需要 HTTPS 和支持 WebAssembly、Web Locks 的较新浏览器。通过独占锁限制同一浏览器来源只有一个编辑标签页；第二个标签页提示关闭原标签页后重新加载。
- 使用 sql.js 执行 SQLite 规则，数据库快照保存在当前来源的 localStorage；离线与不同账号使用独立记录。事务提交遇到存储错误会恢复上次已保存数据库，不把失败写入显示为保存成功。
- 浏览器存储容量通常远小于服务端的 50 MB 文档上限；SQLite 编码、JSON 备份和不同账号共用配额。自动日快照尝试保留最近十四份，配额不足会提示备份失败。请定期导出 JSON，不把浏览器本机副本当作独立灾备。
- 任务、会话及备份均属于网站数据；清理网站数据、关闭无痕窗口或浏览器回收存储可能使其丢失。退出账号返回原离线副本，账号本机副本仍保留。浏览器会话由同源存储保存，未使用 Windows safeStorage 或 Android Keystore；同一浏览器资料的其他使用者可恢复登录。
- 页面加载完成后断网可继续编辑本地任务，联网后重试同步。本版没有 Service Worker、PWA 安装或离线启动缓存，不保证断网时首次打开或刷新页面可用；关闭页面后不在后台同步。
- 原 `/prototype/index.html` 仍是仓库本地的固定日期演示；正式网页版使用独立构建入口，不迁移原型 localStorage 数据，可通过 JSON 恢复导入。

## 构建和腾讯云部署

开发机 Node.js 24，安装仓库依赖后执行：

```powershell
npm ci
npm run build:web
node --test web/runtime.test.mjs
```

`dist/web/` 包含 HTML、应用与适配层 bundle、样式、sql.js JS / WASM 与许可证。构建只打包浏览器依赖，不包含服务器配置、SMTP、账号数据库或本机会话。构建产物不提交 Git，Windows / Android 无需为纯网页版变更重建安装包。

当前服务器沿用 [云同步部署说明](云同步部署说明.md) 中的 Linux、Nginx、HTTPS 与 `toz-sync.service`。网页为静态文件，无新业务进程；API 仍在同一来源的 `/auth/*`、`/account/*`、`/sync` 和 `/health`，不增加 `/toz` 前缀。Nginx `/toz` 跳转 `/toz/`，后者映射 `/opt/toz-web/current/`，根路径保留原同步服务路由。

部署步骤（管理员通过 SSH 上传，不将登录凭据写入仓库）：

1. 将 `dist/web/` 完整上传到新的 `/opt/toz-web/releases/<发布标识>/`，每次发布使用新目录，避免覆盖正在使用的版本。
2. 上传 `sync-server/deploy/nginx.conf` 为 `/opt/toz-web/nginx-next.conf`，上传 `scripts/activate-web.sh` 为 `/opt/toz-web/activate-web.sh`。
3. 执行 `bash /opt/toz-web/activate-web.sh /opt/toz-web/releases/<发布标识> /opt/toz-web/nginx-next.conf`。脚本校验必要文件，备份现有 Nginx 配置，切换 current 软链接，执行 `nginx -t`、重载及页面 / 健康探测；失败恢复旧配置及原软链接。脚本针对当前已具备 IP 证书的服务器，不承担全新服务器初始化。
4. 核对 `/toz` 跳转、`/toz/` 和资源 HTTP 200、WASM `application/wasm`、健康接口 200、无令牌同步接口 401；在浏览器打开页面。必要时将 current 切回旧版本并恢复脚本输出的 Nginx 备份，再执行配置检查与重载。

本次部署目录 `/opt/toz-web/releases/20261025-web1`，current 指向该目录。保留原同步数据库、私有环境文件、Node 版本、其他 Docker 业务和证书续期服务。网页使用同源 CSP、禁止嵌入、禁止 MIME 嗅探、资源重新验证缓存；不加载外部 CDN。

## 域名 HTTPS 配置（2026-11-02）

`www.lyy12.cn` 的 A 记录已指向 `82.157.65.130`。新增 `/etc/nginx/conf.d/toz-domain.conf`，对应仓库 `sync-server/deploy/nginx-domain.conf`；IP 虚拟主机继续由 `toz-sync.conf` 提供，443 明确设置 `default_server`，确保不发送 SNI 的 IP 客户端仍获得 IP 证书。域名使用独立证书与同一静态目录 / 同步后端，不重建网页资源或迁移数据库。本次只配置 `www.lyy12.cn`，未配置裸域名的证书与跳转。

首次部署先仅启用域名配置的 80 端口部分，让 `/.well-known/acme-challenge/` 指向 `/var/lib/toz-acme`，再用现有 ACME 账号签发：

```bash
/opt/toz-sync/certbot/bin/certbot certonly --webroot \
  --webroot-path /var/lib/toz-acme --cert-name www.lyy12.cn \
  -d www.lyy12.cn --non-interactive --agree-tos
```

证书存在后安装完整域名配置，同时确认 IP 配置的 443 默认虚拟主机标记，执行 `nginx -t` 再重载。域名证书路径 `/etc/letsencrypt/live/www.lyy12.cn/`，本次证书到期日 `2027-01-31`；私钥只留服务器，不进入仓库。原 `toz-cert-renew.timer` 每日两次执行通用 `certbot renew`，同时覆盖域名与 IP 的续期，成功后重载 Nginx，需保持公网 80 可用。

本次原 IP 配置及域名 HTTP 过渡配置备份在 `/opt/toz-web/config-backups/domain-20261102/`。回滚时先移出新增域名配置、恢复备份的 IP 配置，再检查并重载；不要仅取消 IP 的默认标记而保留排序靠前的域名 TLS 配置，否则 IP 的无 SNI 握手可能收到域名证书。网页后续发布仍使用现有 current 软链接和发布脚本，域名配置作为独立文件保留。
