# ToZ 开发需求文档

文档基线：应用 v0.4.4 · 2026-10-22 核对

初稿日期：2026-10-20 · 当前 Windows 已交付，iOS 待开发
产品主张：计划可以改变，开始值得被记住。

当前实现状态：Windows v0.4.4；Electron + Node 内建 SQLite + NSIS。先读 [项目现状](项目现状.md)；本文当前规则与后续目标已分开。使用与构建见 [Windows 安装版说明](Windows安装版说明.md)。

## 1. 产品目标

为个人提供完全离线的日常待办工具。主客户端用于拆分、安排和回顾任务；桌面透明浮窗用于随时查看、独立新增、完成和延期今日任务。最重要的是：任务延期后仍能看到最初何时开始、原本何时计划完成、改期过几次，以及每次改到哪一天。

本稿将“子集”理解为子任务；“每日待办”首先指每日任务视图，当前已支持按日、周、月、年自动生成独立周期实例。首版做 Windows，iOS 为后续独立交付，不在首版承诺跨端同步。

## 4. 日期与时长：不可混淆的业务规则

### 4.1 当前日期字段

| 字段 | 含义 | 当前修改规则 |
| --- | --- | --- |
| `createdAt` | 创建时刻，UTC 时间戳 | 新建写入；旧任务可能缺少 |
| `planStart` | 计划开始日 | 可调整，现有任务变更追加 `plan_start`；不等于已开始 |
| `plan` | 当前计划完成日 | 通过改期调整，追加对应事件 |
| `initialPlan` | 第一次非空计划完成日 | 首次非空后锁定，改期不能覆盖 |
| `started` | 首次实际开始的本地日期 | 第一次开始后锁定；未开始为 null |
| `startedAt` / `startedTimezone` | 首次开始的 UTC 时刻 / IANA 时区 | 点击开始记录，正常提交保护；旧任务可能缺少 |
| `completedDate` | 最近一次完成的本地日期 | 完成时设置，重开清空；原完成时刻保留在事件中 |

新建不等于开始，不根据创建日期伪造持续天数。当前没有外部硬截止字段或逐项编辑历史开始日期的导入向导；导入是整份 schema 1 备份恢复，保留原有事实，不合成旧记录缺失的开始信息。产品和数据库约束不等于对拥有本机数据库权限的人提供防伪证据。

### 4.2 当前统计口径

- 持续天数：开始日计第 1 天；未完成取 `max(0, dayDiff(started, TODAY)) + 1`，完成取 `completedDate` 为终点。`TODAY` 是当前设备本地日期；日期差按保存的 ISO 日期计算。
- 已记录首次开始时区，但尚未实现固定在首次时区计算后续的“今天”；不要将这项待开发目标当作现状。
- 未开始显示“尚未开始”，持续天数为空；允许直接完成而不伪造开始。重开保留首次开始和此前完成事件。
- 延期次数只数 `later`；同一计划起止重复提交不追加事件；只变更起点记 `plan_start`，不计延期。
- 累计后移天数为每次 `later` 的正日差之和，提前不冲销；当前无 `reverted_by` 撤销排除逻辑。
- 暂停 / 继续、实际投入、子任务工时汇总和独立日期仍是后续目标。

例如 10/12 开始、10/15 最初计划，后改为 17、19、20 日，截至 10/20 为持续 9 天、延期 3 次、累计后移 5 天。这不是实际工作小时数。

## 5. 当前核心流程

### 5.1 新建、开始与完成

1. 新建填写标题、说明、分区及可选起止；支持 1 天 / 3 天 / 1 周 / 2 周。起点超过既有终点时表单将终点带到起点，领域层拒绝倒置区间。
2. 写入任务与 `create`，`started=null`、`done=false`、`top=true`；新任务插入置顶组最前，旧任务不批量改写；状态由开始和完成字段推导，不使用初稿的独立状态枚举。
3. 点击开始记录首次日期、时刻、时区并追加 `start`；重复开始不重写。完成记 `complete`，重开记 `reopen`。
4. 仍有未完成且未删除子任务时不能完成父任务。全部子任务完成不会自动完成父任务。
5. 重新打开一个子任务或恢复未完成子任务时，若父任务已完成，则一并重新打开父任务并保留足迹。
6. 编辑任务标题 / 说明 / 分区不改日期；任务右键迁移分区追加来源与目标足迹，周期只影响本期。

### 5.2 延期与改期

1. 改期弹窗显示首次实际开始及当前计划；允许修改计划起点与有效完成日，首次实际开始保持锁定。
2. 无完成日到有效日期记 `schedule`；晚于原计划记 `later`，提前记 `earlier`；起点变化另记 `plan_start`，原因可选。
3. 新建可不排期；当前 `reschedule` 要求有效完成日期，不支持清空已有完成日。
4. 任务与事件在同一事务提交，按全局版本号拒绝过时窗口覆盖，不把跨日归入遗留当作自动延期。
5. 子任务没有独立计划，不存在父子排期联动；外部硬截止、撤销改期和撤销统计属于待开发能力。

### 5.3 今日、日历与浮窗

- 今日集合排除已删除 / 取消项。未完成任务满足实际开始、计划开始或计划完成不晚于今天之一时进入今日；今日完成按 `completedDate` 归组。未开始且纯未来安排进入即将到来；无日期未开始任务留在全部任务。
- 日历起点取计划开始与实际开始较早者，否则回退到计划完成日。普通未完成任务延伸至计划完成、起点和今天中最晚者；完成后止于实际完成日。
- 周期任务在月历只显示 `repeatDate` 对应的本期日期（例如每周指定星期、每月 10 日、农历换算日），取消它在日历上的延续显示。开始、延期、完成与重开均不拉长或移动该日历标记；任务及其历史、今日逾期处理和后续周期规则保持原有语义。甘特图仍使用原始任务区间。
- 月历共享同一个任务，跨天完成即完成整个任务；每周合并为横条，默认五行，展开该周查看全部；月计数按任务 ID 去重。
- 浮窗下拉分区筛选同时影响清单、计数和轮播；子任务默认收起，可展开操作。新任务默认置顶，任务置顶与窗口始终置顶分开；浮窗添加待办打开独立小窗口，保存同步主界面与浮窗，取消不写入。
- 浮窗标题空白处双击展开 / 收缩；折叠每四秒轮播今日未完成任务，滚轮切换，点击打开详情。主标题栏的浮窗按钮单 / 双击均切换可见性，一次双击只切换一次。
- 原生窗口通过同一个主进程写服务保存并广播。日期在定时检查与获得焦点时刷新；完整时区 / 休眠组合仍需专门验证。

## 6. 信息架构与界面

### 6.1 主客户端

三栏结构：左侧导航 / 中间待办 / 右侧详情。

- 导航：今天、日历、甘特图、即将到来、全部任务、延期记录、已完成、分区、数据与设置。
- 列表：日期、完成进度、快捷新建、检索；卡片显示标题、项目、持续天数、延期次数、子任务进度。
- 详情：标题与状态、首次开始（锁形标识）、计划起点、最初计划、当前计划、持续天数、延期统计、子任务、说明、事件时间线。
- 时间线：按操作时间倒序；延期项突出 `旧日期 → 新日期`、本次后移天数、原因和操作时间；可切换“全部 / 仅延期”。
- 月历：周一到周日七列，提供上月、下月与回到今天；每周默认最多五行跨日条，超出可展开本周全部事项，之后可收起。点击事项在侧边打开详情，点击日期新建该日待办。
- 普通任务在月历按区间逐日展示同一个任务，起点优先取计划开始与首次实际开始中较早的日期；旧数据无计划开始时使用首次实际开始，否则使用计划完成日。未完成区间结束为计划完成、今天和起点中的最晚日期；完成区间止于实际完成日。周期实例仅在每期日期点性展示，例外见第 5.3 节。延期延长区间，首次实际开始不变。当前按周合并为最多五行，可展开；月任务总数按任务 ID 去重。未排期但已实际开始的任务也从开始日展示至今天。
- 日期选择器：新建与调整计划复用同一套中性灰色交互日历组件，支持月份切换、今天、已选日期、键盘方向键与 Esc 关闭，避免系统原生日历与界面风格不一致。整体视觉依据用户提供的 macOS 截图，使用中性窗口、半透明材质和多彩项目标记。
- 延期记录：可跨任务检索，点击定位详情；统计次数与累计后移分别呈现。

### 6.1.1 甘特图

- 使用原有任务起止区间（周期任务也保留实际区间），按项目分组，可折叠。顶部日期和左侧任务列固定，支持横向 / 纵向滚动。
- 周 / 月时间尺度、前后导航、今天标线、任务天数、子任务进度；越界时间条裁剪，完整日期由提示保留。
- 项目 / 状态 / 关键词筛选；未排期入口和区间外定位；点击查看详情、完成 / 重开，排期通过已有弹窗提交并追加历史。
- 首版不含拖拽改期、任务依赖、负责人、基线。侧栏搜索可直接输入并检索全部任务，Ctrl+K 聚焦。

### 6.2 桌面透明窗口

- 原生默认宽 336、高 550 逻辑像素；窗口限制宽 280–480、高 64–900，折叠内容高度 68；列表内部滚动。实际保存尺寸与 DPI 下的取整以窗口 API 为准。
- 顶部：拖动区域、今日日期、完成比例、置顶切换、折叠与打开客户端。
- 主体：任务标题最多两行，完成圆钮、延期入口、小号持续天数/延期次数。
- 底部：快速新增打开独立小窗口，不显示主界面；沿用标题、起止、周期、分区和说明表单，默认沿用浮窗筛选分区；保存后关闭并同步，Esc / 取消 / 关闭不创建任务，重复点击聚焦已有草稿。标题与操作区固定，内容独立滚动。透明度入口；空状态显示“今天已安排妥当”，可以继续新建。
- 面板背景透明度可调 35%–95%，文字不跟随整体降透明；模糊效果与透明度分开设置。
- 浮窗默认不始终置顶，用户可开启；默认不点击穿透。穿透开启后整窗不可交互，托盘和全局快捷键必须能恢复。
- 托盘菜单：显示主界面、显示/隐藏浮窗、解除穿透、备份、退出。
- 关闭主窗口默认收至托盘；退出必须退出两个窗口。浮窗隐藏后可通过托盘恢复。
- 保存显示器、位置、尺寸与透明度。显示器断开后夹回现有工作区；适配 100%/125%/150%/200% 缩放。
- “贴在桌面”和“置顶悬浮”是不同窗口行为。首版交付普通透明悬浮窗口，不承诺 Win+D 后仍保留或置于桌面图标后。

## 7. 当前数据结构与一致性

实际采用 Electron 主进程中的 Node 内建 SQLite，前端只通过受限 preload / IPC 访问。不是 Rust 核心，也没有独立 work_logs、多级子任务或 projects 表。

```text
meta(key PRIMARY KEY, value JSON)
  schema / version / recurrences / projects / preferences / settings / 窗口位置等
tasks(id PRIMARY KEY, started, initial_plan, data JSON)
events(id PRIMARY KEY, task_id REFERENCES tasks(id), data JSON)
```

任务 JSON 内嵌 `subtasks` 和 `events`；完整字段导航见 [项目现状](项目现状.md)。schema 1 保留可选字段兼容，不能将初稿的蛇形字段名直接当作当前数据库列。

- 首次开始日期和最初计划由 SQLite 更新触发器与提交检查共同保护；开始时刻和时区在应用提交边界保护。旧任务的缺失可选字段不得随意补造。
- 并发采用快照的全局 `version`，在 `BEGIN IMMEDIATE` 中比较后提交，不是逐任务 `UPDATE ... WHERE version`。
- 正常提交检查旧任务和事件保留、日期调整必须有事件；常见事件包括 `create/start/complete/reopen/later/earlier/schedule/plan_start/edit` 及分区、子任务、删除恢复事件。
- 分区信息与显示偏好保存在元数据；更名同步任务、周期、颜色及筛选，子任务普通删除使用 `deletedAt`。
- `Store.purge` 是经确认、仅针对已删除对象的永久删除事务；`Store.restore` 是确认后的全量恢复。它们与普通提交的历史只追加规则分开，不得通过放松 `commit` 来实现删除。
- 周期模板和实例以 `repeatId/repeatDate` 关联；删除本期不影响其他期次。永久删除追加模板 `excludedDates`，常规保存不得清除以免补回。
- 任务最多 50,000 项、周期模板与分区各最多 1,000 项、快照校验上限 50 MB；这些是代码限制，不是性能验收结果。

## 8. 当前本地保存与备份

- 正式数据通常位于 `%APPDATA%/ToZ`，以设置页实际目录为准；数据库为 `toz.sqlite`。验证必须用独立 `.runtime/`，不得覆盖正式数据或启动项。
- 启动创建当前表结构并执行 SQLite `quick_check`；支持 schema 1 的缺省字段兼容，不承诺通用数据库迁移向导或迁移前自动备份体系。
- 正常任务提交和永久删除成功后尝试生成当日最新完整 JSON 快照；同日覆盖同名快照，保留最近十四份，不是七份日备份加四份周备份。
- 完整导出包含任务、事件、周期、分区与显示信息；单任务导出仅保留该任务，周期副本停止重复。没有工时或 CSV 报表。
- 恢复前验证格式并显示任务数量确认；恢复前保存 `before-restore-*.json` 安全副本，再事务替换。系统自启动等本机设置保持不变。
- 任务写入失败会显示保存失败；自动备份失败通过反馈提示，不应声称已经实现所有错误的持久重试界面。
- 永久删除不会清除旧快照、安全副本或已导出的文件，主动恢复旧备份仍可能恢复其中数据；确认窗口必须说明。
- 无账号、业务服务器或自动云同步。Electron 运行时随安装包分发，不使用初稿的 WebView2 安装方案。

## 9. 当前技术方案与历史候选

已采用：Electron 44.9.1 + JavaScript ES modules + Node 内建 SQLite + electron-builder / NSIS，开发使用 Node.js 24；具体依赖以 `package.json` 和锁文件为准。

主客户端和透明浮窗是两个 Electron 窗口，启用 contextIsolation、禁用渲染进程 Node 集成，并使用受限 preload 和按窗口校验的 IPC。透明、无边框、置顶、穿透、托盘及启动项由主进程实现，CSS 只负责前端材质。

Tauri 2 + TypeScript / Rust 是初稿候选，没有在当前仓库实施；不应据此新建 Rust 核心或将原生 IPC 迁走。Windows x64 已交付，其他 Windows 版本、全部 DPI 组合及 iOS 需各自验证。iOS 还需移动端架构、构建签名和真机验收，不能由桌面能力直接推导。

开源产品检索为第 2 节标明日期的历史调研，不代表本次重新核验了第三方产品或许可证。

## 13. v0.3.0 需求及验收

1. 农历周期：新增月 / 年安排、月日选择和闰月策略；日期旁显示农历。三十遇小月取廿九，次个大月恢复；仅闰月的无对应年份跳过，不伪造日期。支持 1900–2100 年；每期仍独立记录，公历与农历不漂移。保存公历日期、农历规则和期次标识，旧公历规则兼容。
2. 项目自定义：新建 / 双击或编辑按钮修改名称与颜色；长按拖动改变顺序。更名须在同一事务迁移任务与周期归属，并为任务追加更名足迹，不改已有事件、首次开始或最初计划。
3. 浮窗项目筛选：下拉全部 / 单项目，进度、清单、缩略轮播共用筛选，持久保存且随更名更新。
4. 日历连续时间条：同任务每周内合并跨日显示，跨周裁剪续接；不同任务重叠时分配独立行，默认最多五行，可展开本周所有事项。完成为绿色，项目自定义色用于未完成事项。
5. 任务置顶：主列表、浮窗、详情、日历与甘特图提供图钉开关；最新置顶进入置顶组首位，多个置顶任务可再排序。窗口始终置顶开关独立。
6. 拖动排序：菜单、项目、任务长按约 380ms 激活，普通单击 / 双击保留原功能。菜单、项目各自排序；任务同完成 / 置顶组内排序，全局共用，不更改任务日期。指示线、Esc 取消、Alt + 方向键备用操作。持久顺序在重启、备份恢复与两个窗口间一致。
7. 数据兼容：旧 schema 1 无显示设置时采用默认值；项目列表省略时不丢弃已有空项目；改名不允许覆盖已有项目或遗漏任务；单任务导出仅保留自身排序 ID，周期副本停止重复。

技术：内置 [lunar-javascript](https://github.com/6tail/lunar-javascript) 1.7.7，MIT 许可保留在 prototype/vendor。换算不联网。领域测试覆盖春节、闰六月、小月、结束日期、离线补齐、跨周条、原子更名、排序保存和旧格式。


## 14. v0.4.0 右键操作与恢复

分区、任务、子任务提供同主题右键菜单；子任务可改名并记录旧 / 新名称。删除使用 deletedAt 软删除，事件继续只追加；子任务数组保留已删除记录，正常视图、日历、甘特图、浮窗、统计与完成校验只处理可见记录。回收站可恢复三类内容，提供搜索；单组超过 100 条可检索。

分区保留注册名称与颜色，preferences.projectTrash 保存删除模式和目标分区。迁移模式在同一事务更新全部所属任务及周期模板，任务追加 project_move 足迹；连带删除则软删除任务并停止所属周期。恢复原分区不逆转迁移，恢复连带删除仅找回当时随之删除的任务，不覆盖此前单独删除的任务，不重启已停止周期。最后一个分区删除后创建可用的“未分区”。

## 15. v0.4.1 任务右键切换业务分类

业务分类沿用现有分区：任务菜单的「移动到分区」展开二级列表，按分区顺序显示有效分区、颜色与当前归属勾选；悬停、点击、方向键均可展开。单次选择只迁移该任务，子任务跟随；追加 project_move 的 fromProject / toProject 足迹，保留首次开始、所有计划、完成状态、置顶、顺序和既有历史。周期实例仅移动本期，其余实例和模板保持归属。客户端和悬浮窗同步更新分区计数、筛选与颜色。

菜单靠右向左展开，窄窗口必要时调整一级菜单位置以容纳两列；长名称截断并提供完整提示。已删除分区不提供为目标，目标失效或多窗口版本冲突时提示重新操作。

## 16. v0.4.2 回收站永久删除与可持续关闭

回收站包含逐项彻底删除和全量清空，先显示准确范围与计数，再确认执行；搜索不限制全量清空范围，空列表禁用清空。确认默认选中取消。主存储提供独立 purge(request, expectedVersion) 事务，仅读取已删除对象；正常提交仍限制历史只追加、首次开始与最初计划不变。并发版本变化拒绝执行，要求重新确认。

彻底删除任务移除任务、子任务和 events 行；彻底删除子任务移除子项，父任务原足迹保留并追加匿名清除记录。分区清除关联仍在其内的已删除任务与无引用停止周期，保留已经迁出的正常任务；仍被迁出任务引用的停止周期移到有效分区保留来源。其他回收站分区指向被清除目标时更新关联并标记 targetPurged，仍可恢复空分区。

周期模板可包含 excludedDates；只由永久删除事务追加，正常写入不可移除或覆盖。生成跳过已清除日期，继续寻找下一可用期次；备份 / 恢复与旧 schema 1 格式兼容。旧备份和已导出文件不会自动清除，确认窗口明确说明。

设置和回收站使用 scroll-dialog：标题和关闭按钮不参与滚动，只有 dialog-body 滚动。回收站底部关闭按钮同样固定。浅深两种主题、820 / 700px 窗口均需在内容滚到底部后确认关闭按钮坐标稳定、未被遮挡且可直接点击。

SQLite 校验拒绝未经足迹记录的删除 / 恢复 / 子任务改名，拒绝直接移除任务和子任务历史；首次开始与最初计划仍受原有约束。旧备份没有删除元数据时沿用可见状态。JSON 备份和原生双窗口同步包含回收站数据。

开始日期选择若超过已填写的完成日期，界面将完成日期同步到同一天；其他日期校验保持有效，调整计划仍在保存时追加审计事件。

## 17. v0.4.3 新建置顶、浮窗新增与周期日历展示

新建普通任务及新生成周期期次使用 top=true，并将新 ID 插入任务排序最前；已有任务缺省 top 或明确取消置顶的选择不改写。仍可通过图钉取消置顶或在同组内手动排序。

浮窗“添加待办”和 N 快捷键打开独立新增窗口，主界面保持原有显隐。窗口只复用新建表单，支持周期、日期与新建分区；共用 SQLite 写服务、版本冲突检查及广播。保存失败保留草稿并显示错误，刷新版本后可重试；不以打开主界面完成新增。

周期月历取消延续显示，只保留每期日期的点性展示；不删除周期规则或期次，不改写日期与事件。旧周期缺少 repeatDate 时回退计划开始或完成日。普通跨日任务继续按周合并，甘特图区间不变。
