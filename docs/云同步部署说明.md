# Windows 账号与云同步

适用版本：Windows v1.1.2，2026-10-25。

## 使用方式

启动时若没有保存的登录状态，先显示独立欢迎页，可输入邮箱获取六位验证码登录，也可选择“离线使用”；选择完成前不创建任务主窗和浮窗。已有保存会话直接进入，可断网使用本地账号副本。设置 → 账号与同步保留后续登录、绑定与同步管理入口。首次验证自动注册，验证码十分钟有效、最多尝试五次、单次使用；同一邮箱一分钟内不能重复发送，每天最多二十封。同一 IP 每小时最多二十次发送和六十次验证。邮件通过配置的 QQ 邮箱 SMTP 加密发送。退出后再登录需要新的验证码。

首次在有离线任务的电脑登录时，可取消、保留离线数据并进入账号，或复制离线数据到账号。复制仅在该账号首次建立本地副本时执行；原离线数据保留，退出后返回欢迎页，再次选择离线使用后显示。已有账号副本不会被重复导入覆盖。账号数据库位于本机数据目录的 `accounts/<账号 ID 的 SHA-256>/toz.sqlite`，不同账号互相隔离。已退出账号的本地副本仍保留，不属于远程注销或安全擦除。

登录后约每十五秒同步，也可点击“立即同步”。断网可继续编辑，恢复后重试。同步任务、子任务、足迹、回收站、分区、分区颜色与周期规则；任务硬删除及周期排除日期一并传播。任务排序、菜单排序、浮窗分区筛选、外观、阅读、启动与窗口选项保留在各电脑，不进入云端文档。

左下角账号入口替代设置及回收站快捷图标，菜单提供设置、账号与同步、上传头像、恢复默认头像和退出。未登录时显示离线使用，头像相关操作不可用；回收站仍从顶部任务菜单进入。上传可选不超过 5 MB 的 PNG / JPEG / WebP，客户端居中裁成 128×128 PNG，服务端保存，其他电脑每次同步时更新账号头像。

“绑定另一个邮箱”要求已登录并验证新邮箱。绑定成功后，两个邮箱均可登录同一个账号；已属于其他账号的邮箱不能直接绑定。服务端身份表为多种联系方式预留 `kind`，但手机号验证码、手机号绑定与登录尚未接入，没有短信供应商时不显示可操作入口。

## 合并与冲突

客户端在账号 SQLite 元数据 `cloudBase` 中保存上次同步成功的业务文档。以它为基线，比较本机与云端：只改一侧的记录自动接受，不同任务自动合并；同一任务的不同修改、删除与编辑发生竞争时暂停上传，保留双方版本。各电脑独立生成的同一期未修改周期任务可自动去重。

在账号页选择冲突项保留本机或云端版本，并完成原生确认。普通记录选择仅作用于冲突项，其他修改仍合并；分区删除 / 更名、周期及父子约束无法联合满足时，需要选择完整的一侧。确认前后数据变化会拒绝本次处理。替换本地业务数据前生成 `before-restore-*.json` 安全副本；这些副本不自动清理。云端保留最近三十个被替换的文档版本，目前恢复需管理员操作，尚无历史版本恢复界面。

服务器使用账号内单调递增版本及事务 CAS，拒绝过时上传，不使用最后写入者静默覆盖。传输采用完整业务文档，尚非增量协议；最大文档 50 MB，适合当前个人待办规模，大数据量与低带宽性能尚未专项验收。发布同步结果期间暂时拒绝普通任务写入并提示稍后重试，避免上传等待中的本地更新被覆盖。普通 `Store.commit` 的首次开始、最初计划及历史保护保留；远端删除与已确认冲突通过单独校验、备份和替换事务应用。

## 当前部署

- 服务地址：`https://82.157.65.130`，客户端默认地址位于 `desktop/cloud.cjs`。本版没有客户端服务器地址设置。
- Linux：CentOS Stream 9；独立 Node.js v24.18.0 位于 `/opt/toz-sync/node`，不替换系统 Node。
- 程序目录：`/opt/toz-sync/app`，包含 `sync-server`、`desktop/store.cjs` / `sync-model.cjs` 及其依赖的领域模块和 `prototype/vendor`。
- 业务进程：`toz-sync.service`，专用系统用户 `toz-sync`，监听 `127.0.0.1:8787`，由 Nginx 的 443 反向代理；80 供证书验证和 HTTPS 跳转。
- 私有环境配置：`/etc/toz-sync/server.env`，root 只读写（600），目录 700；实际 SMTP 授权码与 OTP 密钥只放在该配置中，不进入仓库或安装包。字段示例为 `sync-server/config.example`。
- 数据：`/var/lib/toz-sync/sync.sqlite`，WAL 模式；目录由专用用户持有，权限 700。用户、账号头像、已验证联系方式、验证码摘要、会话摘要、当前文档、三十个旧版本和限流计数存于其中。v1.1.2 启动时为旧 users 表补充可空 avatar 列；服务端已更新，迁移前使用 SQLite VACUUM INTO 备份到 `/var/lib/toz-sync/before-avatar-20261025.sqlite`。
- HTTPS：Let’s Encrypt IP 证书，Certbot 5.8.0，`shortlived` 配置；当前签发证书在 2026-10-31 到期。`toz-cert-renew.timer` 每日两次检查续期，成功后重载 Nginx。证书有效期短，服务器维护时必须保持该定时器和公网 80 可用。
- 现有其他 Docker 业务保留，未替换系统 Node 或重启其容器。

IP 证书操作依据 [Let’s Encrypt Certbot 官方说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)。腾讯云安全组需放行 80/443。部署不意味着对所有腾讯云网络策略和合规场景做出保证。

## 维护与重新部署

服务端要求 Node.js 24。在完整源码目录下运行 `npm --prefix sync-server ci --omit=dev`，然后使用 `sync-server/deploy/toz-sync.service` 配置服务。部署文件清单可参考当前 `/opt/toz-sync/app`：服务端依赖 `desktop/store.cjs`、`desktop/sync-model.cjs` 以及 `prototype` 下的 domain、lifecycle、trash、preferences、projects、recurrence、lunar 与 vendor；不能只复制 `server.cjs`。

新服务器须先准备独立 Node 24、Nginx、Certbot >=5.4、专用用户及持久化目录，参照 `sync-server/config.example` 配置环境，再安装 systemd 服务。首次申请 IP 证书前，仅启动 80 的 ACME webroot 配置，申请成功后启用仓库中的完整 Nginx 配置，并按实际 IP 调整路径和客户端地址。完整 Nginx 配置依赖已存在的证书，不能在签发前直接启动。初次命令示例：

```bash
certbot certonly --non-interactive --agree-tos --email YOUR_EMAIL \
  --preferred-profile shortlived --webroot --webroot-path /var/lib/toz-acme \
  --ip-address YOUR_IP
```

常用检查：

```bash
systemctl status toz-sync nginx toz-cert-renew.timer
curl -fsS https://82.157.65.130/health
journalctl -u toz-sync --since today
/opt/toz-sync/certbot/bin/certbot renew --dry-run
```

不要直接打印环境文件、验证码或会话。验证码使用服务端密钥 HMAC 摘要保存；会话为随机令牌，仅摘要入服务端数据库，三十天到期，在线退出撤销当前令牌。Windows 会话文件由 Electron `safeStorage` 加密令牌。离线退出只清除本机登录状态，无法保证立即撤销服务器令牌。暂未提供设备列表、全设备注销、端到端内容加密或异地灾备；云端可读取业务文档。

备份服务端时使用 SQLite 在线备份 API，或停服务后同时处理数据库及 WAL；不要在运行中只复制主文件。已有三十个文档旧版本不能代替独立服务器备份，本轮未配置异地备份。

## 定向验证

`npm run test:cloud` 覆盖同步与直接受影响的存储、阅读设置；不是全量测试。原生账号流程使用隔离数据：

```powershell
node_modules/.bin/electron.cmd . --disable-gpu --cloud-ui-test --toz-data=.runtime/独立目录 --smoke-result=artifacts/cloud-ui/result.json
```

该 UI 检查使用内置隔离测试服务与模拟邮件，不发真实邮件，也不接触正式 `%APPDATA%\ToZ`。真实服务器邮件另行检查，SMTP 接收成功不等于人工确认邮件已到收件箱。两客户端同步由隔离的两个 Store / Cloud 实例验证，尚未在两台实体 Windows 电脑上联机验收。未运行完整测试和完整安装 / 卸载验收。

v1.1.1 的启动选择定向检查使用 `--entry-ui-test` 替代上述命令中的 `--cloud-ui-test`，同样要求独立 `.runtime/` 数据目录；覆盖欢迎页、离线进入、欢迎页登录、退出返回欢迎页与保存会话恢复，不进入完整 smoke。
